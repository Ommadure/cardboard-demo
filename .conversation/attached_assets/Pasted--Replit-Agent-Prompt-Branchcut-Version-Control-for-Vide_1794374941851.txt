## 1. Product overview

**Name (working):** Branchcut
**Tagline:** Version control for video timelines.

Code has git. Video editing has nothing: people end up with files named `final_v3_actual (1).mp4`. Branchcut is a prototype showing what git-style version control could look like for a video **timeline** (not the video files themselves). It lets two editors branch from the same cut, work in parallel, compare versions visually, and merge them, with conflicts shown in a way an editor can resolve without knowing anything about git.

**Context:** This is an independent prototype inspired by the "Version Control" problem in the public "Hard problems" page of the AI video editor Cardboard (cardboard.ai). It is **not affiliated with Cardboard** and uses a simplified, invented timeline format. Show this disclaimer in the app footer: *"Independent prototype inspired by Cardboard's public 'Hard problems' page. Not affiliated. Uses mock data."*

**Primary audience of the demo:** startup founders and engineers who will watch a 45-second screen recording and might try the live demo. First impression and clarity matter more than breadth.

### 7.3 Data model (TypeScript)
```ts
export type TrackId = 'V1' | 'V2' | 'A1' | 'A2' | 'A3' | 'C1';
export type EffectId = 'fade-in' | 'fade-out' | 'warm' | 'cool' | 'bw';

export interface Clip {
  id: string;            // STABLE across versions; this is what makes "moved" different from "deleted + added"
  label: string;
  trackId: TrackId;
  sourceId: string;      // media source, or 'caption'
  sourceIn: number;      // seconds
  sourceOut: number;     // seconds
  start: number;         // seconds on the timeline
  speed: number;         // default 1
  effects: EffectId[];   // treat as a set (order-insensitive)
  caption?: string;      // captions only
}

export interface Timeline { clips: Clip[]; }   // flat list; trackId on each clip

export interface Commit {
  id: string;
  parents: string[];     // 0 (root), 1 (normal), or 2 (merge)
  branch: string;        // branch it was created on
  message: string;
  author: string;
  createdAt: number;
  timeline: Timeline;    // full snapshot (immutable)
}

export interface RepoState {
  commits: Record<string, Commit>;
  branches: Record<string, string>;   // branch name -> tip commit id
  head: { type: 'branch'; name: string } | { type: 'detached'; commitId: string };
  working: Timeline;                  // editable working copy
}

export type ChangeKind = 'added' | 'removed' | 'moved' | 'trimmed' | 'modified';
export interface Change {
  clipId: string;
  kind: ChangeKind;
  label: string;
  detail?: {
    fromStart?: number; toStart?: number;
    fromTrack?: TrackId; toTrack?: TrackId;
    fromIn?: number; toIn?: number; fromOut?: number; toOut?: number;
    fields?: string[];                 // for 'modified'
  };
}

export type ConflictKind = 'field' | 'delete-modify' | 'collision';
export interface Conflict {
  id: string;
  clipId: string;
  kind: ConflictKind;
  field?: keyof Clip;                  // for 'field'
  base?: unknown; ours?: unknown; theirs?: unknown;
  oursDeleted?: boolean; theirsDeleted?: boolean;   // for 'delete-modify'
  collidesWith?: string;               // other clip id for 'collision'
  resolution?: 'ours' | 'theirs' | 'both';
}

export interface MergeResult {
  merged: Timeline;                    // with non-conflicting changes applied; conflicts use ours as provisional value
  conflicts: Conflict[];
  appliedFromTheirs: Change[];
  keptFromOurs: Change[];
}
```

### 7.4 Diff algorithm (`diffTimelines(a, b)`)
1. Index both timelines by `clip.id` (Map).
2. For each clip in B: if missing in A → `added`. Otherwise compare against A and emit (a clip may emit several):
   - `moved` if `start` changed **or** `trackId` changed.
   - `trimmed` if `sourceIn`, `sourceOut`, or `speed` changed.
   - `modified` if `sourceId`, `label`, `caption`, or effects (as sets) changed. Record changed field names.
3. For each clip in A missing from B → `removed`.
4. Return changes sorted by earliest timeline position, then kind. Pure function; no mutation.

### 7.5 Three-way merge algorithm (`threeWayMerge(base, ours, theirs)`)
Compare **per clip id, per field**. Fields: `trackId, sourceId, sourceIn, sourceOut, start, speed, effects (set compare), caption, label`.

For every clip id in the union of base/ours/theirs:
- **Presence logic**
  - In neither ours nor theirs (deleted by both) → drop.
  - Added only in ours, or only in theirs (not in base) → include it.
  - Added in both with the same id → merge field-wise using `base = undefined` (conflicts on differing fields).
  - Deleted in ours, unchanged in theirs (theirs equals base) → delete. Same for the symmetric case.
  - Deleted in one side and **modified** in the other → `delete-modify` conflict (provisional value: keep the deleted state of ours/theirs as it was, mark unresolved).
- **Field logic** (clip exists in both ours and theirs):
  ```ts
  function mergeField<T>(base: T, ours: T, theirs: T) {
    if (eq(ours, theirs)) return { value: ours };
    if (eq(base, ours))   return { value: theirs };   // only theirs changed
    if (eq(base, theirs)) return { value: ours };     // only ours changed
    return { conflict: { base, ours, theirs } };
  }
  ```
  `effects` are compared as sorted arrays. A conflict uses the **ours** value provisionally.
- **Post-merge collision check:** after building the merged clip list, scan each track for overlapping time ranges (`[start, start+duration)`); for each overlapping pair that isn't already part of a field conflict on the same clips, create a `collision` conflict. (Captions and V2 may not overlap other clips on the same track either.)
- Track which changes came from theirs vs ours for the summary lists (`appliedFromTheirs`, `keptFromOurs`) by diffing `base→theirs` and `base→ours` on non-conflicting clips/fields.
- `applyResolutions(result, resolutions)` returns a final `Timeline`:
  - field: choose ours or theirs value
  - delete-modify: `ours`/`theirs` selects which side's state wins (deleted vs kept)
  - collision: `ours` / `theirs` keep one; `both` moves the "theirs" clip to an overflow track (add `V3` dynamically if needed, but only used for this case)
  - Re-run collision detection after applying; the final timeline must contain no overlaps.

### 7.6 Plain-English summaries (`summary.ts`)
Deterministic templates, e.g.:
- added: `Added "{label}" on {track} at {start}s`
- removed: `Removed "{label}" from {track}`
- moved: `Moved "{label}" from {fromStart}s to {toStart}s` (or `from {fromTrack} to {toTrack}`)
- trimmed: `Trimmed "{label}" from {oldDur}s to {newDur}s`
- modified: `Changed {fields} on "{label}"` (e.g. "Added effect fade-out")
- conflict: `"{label}": {field} was set to {ours} on your branch and {theirs} on theirs`

Format seconds to at most one decimal.
